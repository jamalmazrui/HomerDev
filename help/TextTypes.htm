Text Types

A Homer database says what kind of text a column holds through the column’s declared type. SQLite gives any declared type that contains TEXT the text affinity, so a column declared TEXTJSON or TEXTINIX stores ordinary UTF-8 text, exactly as TEXT would, while its name tells a program the text’s format – so the program can read, check, edit and convert it as that format.

This is the vocabulary, in alphabetical order. TEXTLINE and TEXTTIME hold one value; every other type holds lines. The kit keeps it in two twins, Homer.TextTypes in exec.cs and scripts.py, which must be changed together; the conversion to DbDo format seeds it into each database’s defs, as rows with src DbDo and fld type, so a database describes its own types.

  • TEXTCSV (.csv): Comma-separated values.
  • TEXTDBDO (.dbdo): A DbDo routine of dot-prompt commands.
  • TEXTHTML (.htm): A web page.
  • TEXTICS (.ics): ICalendar events.
  • TEXTINIX (.inix): Homer settings, in sections of key = value lines.
  • TEXTJSCRIPT (.js): A JScript .NET program.
  • TEXTJSON (.json): JSON data.
  • TEXTLINE: One line of plain text.
  • TEXTM3U (.m3u): A playlist.
  • TEXTMARKDOWN (.md): Markdown.
  • TEXTMEMO (.txt): Lines of plain text.
  • TEXTSQL (.sql): SQL statements.
  • TEXTTIME: A date and time, as YYYY-MM-DD HH:MM:SS.
  • TEXTTSV (.tsv): Tab-separated values.
  • TEXTVCAL (.vcs): VCalendar events.
  • TEXTVCARD (.vcf): VCard contacts.
  • TEXTXML (.xml): XML.

A file whose extension is not listed is TEXTMEMO. A few other extensions are read as their format: .html as TEXTHTML, .ini as TEXTINIX, .m3u8 as TEXTM3U, .markdown as TEXTMARKDOWN, .text as TEXTMEMO.

One column, many formats

When one column holds rows of different formats, as DbDo’s files table does – a SQL question in one row, a report definition in the next – the column is declared TEXTMEMO and a kind column names each row’s format in this same vocabulary. Both ways speak one language: the declared type when a column has one format, kind when each row has its own.
